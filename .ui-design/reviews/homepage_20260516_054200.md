## Critical Issues

### Issue 1: Mobile header adds a fourth call path before scroll

**Severity:** Critical  
**Location:** `src/components/layout/SiteHeader.tsx:100-104`, `src/components/sections/Hero.tsx:69-90`  
**Category:** Usability / CTA clarity

**Problem:**  
On viewports below `lg`, the header renders a full-width red **Call {phone}** bar under the logo. The hero immediately below adds **Request Service** and **Call Now**. That is three high-emphasis phone/request actions before the user reads the value prop—then the emergency band adds a fourth phone mention. The gated `MobileStickyCtaBar` fix helps after scroll, but first-load mobile still feels sales-heavy.

**Impact:**  
Violates the “one clear action” goal from the design-critic lens. Increases cognitive load and makes the brand feel pushy rather than trustworthy.

**Recommendation:**  
On homepage only (or when `[data-mobile-cta-sentinel]` is present), demote the header mobile call row to a text link or icon-only affordance, and keep the hero as the single primary conversion pair. Alternatively, hide the header call row until the hero sentinel leaves the viewport (same logic as sticky bar).

**Code direction:**

```tsx
// SiteHeader.tsx — example: suppress mobile call bar on pages with hero sentinel
const suppressMobileCall =
  typeof document !== "undefined" &&
  document.querySelector("[data-mobile-cta-sentinel]");

// In mobile row: render Menu + compact phone icon link instead of full emergency button
```

## Major Issues

### Issue 2: Seven service cards create a long “proof delay” on mobile

**Severity:** Major  
**Location:** `src/app/(site)/page.tsx:31`, `src/components/sections/ServiceCards.tsx:14-17`  
**Category:** Usability / cognitive load

**Problem:**  
`ServiceCards` renders all seven services in a single column on mobile. Reviews and authority sit **below** this block, so users scroll through a full catalog before seeing trust signals.

**Impact:**  
Homepage feels like a directory before it feels like a recommendation. Hurts scanability for cold traffic.

**Recommendation:**  
Pass `limit={4}` (or 5) on the homepage only; add a single “View all services” link to `/services`. Preserves section order; reduces scroll depth ~40%.

### Issue 3: Emergency band copy assumes hero CTAs are still visible

**Location:** `src/components/sections/EmergencyCTA.tsx:14-19`  
**Category:** Usability

**Problem:**

**Impact:**  
Directional copy feels wrong and forces users to hunt for Request Service.

### Issue 6: Redundant `width`/`height` with `fill` at call sites

**Severity:** Major  
**Location:** `src/components/sections/ServiceCards.tsx:28-33`, `src/components/sections/CommercialCapabilitySection.tsx:20-25`  
**Category:** Code / reliability

**Problem:**  
Several `CloudinaryImage` usages pass both `fill` and explicit dimensions. `CloudinaryImage.tsx` currently strips dimensions when `fill` is set, but callers still encode the anti-pattern—easy to regress if the wrapper changes.

**Impact:**  
Previously caused runtime 500s (`width` + `fill`). Fragile for future edits.

**Recommendation:**  
Remove `width`/`height` from all `fill` call sites; rely on `sizes` + parent aspect ratio only.

### Issue 9: Testimonials marquee duplicates content in the DOM

**Severity:** Minor  
**Location:** `src/components/sections/Testimonials.tsx:24, 101-107`  
**Category:** Performance / accessibility

**Problem:**  
Marquee clones the testimonial list (`[...items, ...items]`), doubling screen-reader noise and DOM weight.

**Recommendation:**  
Prefer horizontal scroll snap on mobile (already used for `prefers-reduced-motion`); use marquee only from `md+` or drop duplication and use CSS loop on a single set with careful `aria-hidden` on clones.
